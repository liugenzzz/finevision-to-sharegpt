# 500 万条翻译 · 运行手册

一次约 13 天的任务（4 个实例、实测 4.3 条/秒）。按顺序做，每步都有验收标准，
不通过就别进下一步——13 天的任务，前面省的 5 分钟后面要用几天赔。

## 阶段 0 · 配置

### 0.1 拉代码并重新生成配额

机器上的 `configs/fv_counts.txt` 是真实行数（188 行），比仓库里的准，要保住。

```bash
cd /mnt/si003010kcx0/mmdata/mmcode/finevision-to-sharegpt
cp configs/fv_counts.txt /tmp/fv_counts.mine.txt
git pull origin main
cp /tmp/fv_counts.mine.txt configs/fv_counts.txt

python scripts/plan_sampling.py --counts configs/fv_counts.txt \
    --config configs/translate_zips.json \
    --plan configs/sampling_plan_5m.json --chinese-ratio 1.0 \
    -o configs/translate_5m.json
```

**验收**：`TOTAL` 那行是 **166** 个数据集、5,000,000 条；排除名单 **22 个**；
`the_cauldron` / `Flickr30k` / `RefCOCO` **不在**排除名单里。

### 0.2 图片落盘位置

约 1.3 TB。跑之前改是一行配置，跑完再搬是跨盘拷贝几小时。
编辑 `configs/translate_5m.json`，在 `output_jsonl` 下面加一行：

```json
  "images_root": "/你的大盘/mm_images/images",
```

保持 `<统合目录>/images` 这个形状：JSONL 里的路径相对 `images_root` 的**父目录**，
训练时 `dataset_dir` 指到 `/你的大盘/mm_images`。

### 0.3 后端池对齐实际实例数

`configs/backend_config.json` 里有 5 个条目，其中 `remote-zjlab` 的 key 是占位符。
**要么填上真 key，要么把这一段删掉**——留着的话每次开跑它那 16 路线程都要先失败
20 次才被摘掉，纯浪费。已经停掉的本机实例同样删掉。

**验收**：`backends` 数组里剩下的条目 = 实际在跑的实例数。

## 阶段 1 · 模型通不通

### 1.1 探活

```bash
python scripts/check_backends.py configs/backend_config.json
```

**验收**：每个后端两行（`text` 和 `image`）全 OK。
`image` 那行尤其重要——翻译永远带图发，纯文本模型会条条失败。

常见错误：
- `404 model does not exist` → `model` 字段和实例的 `--served-model-name` 对不上
- `401` → api_key 不对
- 连接被拒 → 实例没起来，或端口写错

### 1.2 量速率

```bash
python scripts/bench_backend.py --port 8002 --concurrency 32 --requests 64
```

**验收**：单条延迟 1 秒以内。到几十秒说明实例有病或者卡被别的进程抢了。

注意「并发 32」那两行的吞吐是**玩具负载**（1×1 像素图、6 token 输出），
真实数据要慢几十倍，不能拿来规划工期。

### 1.3 端到端冒烟

```bash
python -m finevision_to_sharegpt translate-zips --config configs/translate_smoke.json
head -2 output/smoke.jsonl
```

300 条，一分钟内完成。

**验收**：`written=300`、`failed=0`；译文是干净中文；`<image>` 在第一条 human 开头；
没有 `<think>` 残留。

## 阶段 2 · 数据库

```bash
export FV_MYSQL_PASSWORD='你的密码'
python -m finevision_to_sharegpt db-init --config configs/translate_5m.json
df -h /你的大盘
```

**不需要调 `max_connections`。** 连接池已改为有界共享：所有工作线程共用
`mysql.pool_size` 条连接（默认 8），用完即还。翻译并发 272 路，服务端看到的
仍然是 8 条——真实 MySQL 8.4 上实测严格相等。

需要的连接数按这个算，和翻译并发无关：

```
并发运行的进程数 × pool_size + 几条自己用的
```

单进程跑就是 8 条，默认的 151 富余得很。

（旧版手册这里让你执行 `SET GLOBAL max_connections = 500`。那是每线程一条
常驻连接时代的要求，现在既没必要，`fv` 账号也没有 SUPER 权限执行不了；真要
执行得用 root，而 root 是空密码，加 `-p` 反而进不去。）

也**不需要装 mysql 命令行客户端**——所有数据库操作都走 PyMySQL，项目自带。

**验收**：`db-init` 正常返回；磁盘余量 ≥ 1.5 TB。

## 阶段 3 · 开跑

```bash
tmux new -s fv5m
python -m finevision_to_sharegpt translate-zips --config configs/translate_5m.json
```

`Ctrl-B` 然后 `D` 脱离，`tmux attach -t fv5m` 回来。

### 一小时后核速率

```bash
python -m finevision_to_sharegpt db-status --config configs/translate_5m.json
```

`done` 条数 ÷ 已跑秒数 ≈ **4.3 条/秒** 为正常（一小时约 1.5 万条）。
明显偏低就停下来查，别让它带病跑几天。

## 阶段 4 · 日常监控

```bash
tmux attach -t fv5m                                                      # 进度条
python -m finevision_to_sharegpt db-status --config configs/translate_5m.json   # 各集进度
python scripts/db_inventory.py --config configs/translate_5m.json        # 全景
wc -l output/run5m/failed.jsonl                                          # 失败累计
```

**断了怎么办**：直接重跑同一条命令。`resume: true` 加账本去重，已完成的会跳过。

**失败堆积**：看 `failed.jsonl`。集中在长文档数据集（olmOCR、DoclingMatix）且报
`model response did not include message content`，就是 `MAX_LEN 8192` 不够，
改启动脚本 `MAX_LEN=16384` 重启 vLLM——PagedAttention 按实际 token 分配，
调高几乎不花显存。

## 阶段 5 · 补扫（可选，不急）

**默认不用做。** 翻译本身会给它碰到的每一行写英文原文，500 万条自动补齐。
补扫只多覆盖那些永远不会被翻译的行，对动态配比没用。

想让库变成完整目录再做，翻译稳定之后随时可以，并行安全
（`sample_source` 的 upsert 对 `done` 行不降级）：

```bash
tmux new -s fvscan

# 清水位线：不清的话 db-scan 按断点续传，一行都不会读。
# 没有 mysql 命令行也没关系，走项目自带的 PyMySQL：
python -c "
import sys; sys.path.insert(0,'src')
from finevision_to_sharegpt.config_loader import load_zip_task_config
from finevision_to_sharegpt.db.pool import ConnectionPool
pool = ConnectionPool(load_zip_task_config('configs/db_scan_all.json').mysql)
pool.run(lambda c: c.execute('DELETE FROM dataset_cursor'))
pool.close(); print('水位线已清')
"

python -m finevision_to_sharegpt db-scan --config configs/db_scan_all.json --no-images
```
开了之后看半小时翻译速率，掉了就掐掉补扫，随时能重来。

## 跑完之后

```bash
python -m finevision_to_sharegpt db-status --config configs/translate_5m.json   # 确认全 done
python -m finevision_to_sharegpt validate \
    --input output/run5m/train.jsonl \
    --output output/run5m/valid.jsonl \
    --rejects output/run5m/invalid.jsonl
```

之后换配比不用重翻：库里每条同时有英文原文（`sample_source.conversations`）
和中文译文（`sample_translation.conversations`），比例是查询时挑哪一列的事。
