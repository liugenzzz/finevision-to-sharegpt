# 开发文档：分步中间文件 + merge 合并功能

> 文档角色：给**执行编码的 AI**看的需求与验收文档。项目经理（本文作者）负责验收，不直接改代码。
> 日期：2026-07-27　范围：`finevision-to-sharegpt` 的 zip 抽取/翻译流水线 + 新增 `merge` 命令。
> 前置：本项目刚完成「翻译+抽样重构」（见 `docs/refactor/2026-07-27-翻译与抽样重构-开发文档.md`）。本次在其结果之上增量开发。

---

## 1. 背景与目标

现状：`translate-zips` 每个数据集只产出**翻译后**的 per-dataset jsonl（`output/<dataset>/train.jsonl`）+ 一份汇总（`output/train.jsonl`）。使用者希望能拿到**每一步的中间文件**，便于核对、复用、单独重跑。

**目标：**

1. **分层中间文件**：让「抽取+翻译」按步骤留下三层产物——
   - **原始层**（raw）：每个数据集抽出来的**翻译前英文 ShareGPT** jsonl（**新增**）。
   - **翻译层**（translated）：每个数据集**按比例翻译后**的 jsonl（已有）。
   - **汇总层**（combined）：最终合并 jsonl（已有）。
2. **新增 `merge` 命令**：把若干中间 jsonl 合并成一个（拼接 + 按 `id` 去重），输出 jsonl + json。

---

## 2. 已确认的产品决策

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 原始层（翻译前英文 jsonl）| **默认产出**，config 开关可关（`emit_raw`，默认 `true`）|
| D2 | 中间文件布局 | **按数据集分目录 + 步骤名**：`output/<dataset>/raw.jsonl`、`output/<dataset>/train.jsonl`，汇总 `output/train.jsonl` |
| D3 | `merge` 语义 | **纯合并 + 按 `id` 去重**，输出 jsonl+json；**不做**抽样/比例/打乱 |

> ⚠️ 与已删除的老 `mix`/`mixer.py` 的关系：**本 `merge` 不是它的复活**。老 `mix` 带比例/数量抽样（`_resolve_counts`、ratio 逻辑），是造成之前冗杂的一部分。本 `merge` **只做「拼接+去重」**，严禁把 ratio/count 抽样加回来。

## 3. 需求详述

### 3.1 三层产物的定义

以「`translate-zips`，选了 3 个数据集，`chinese_ratio=0.7`」为例：

| 层 | 文件 | 内容 | 现状 |
|----|------|------|------|
| 原始层 | `output/<dataset>/raw.jsonl` | 该数据集**所有被抽中且解析通过**的样本的**英文 ShareGPT 记录**（翻译前，全英文，不管这条后面是留英文还是翻中文）| **新增** |
| 翻译层 | `output/<dataset>/train.jsonl` | 该数据集**按比例翻译后**的记录（中文 + 保留的英文混合）| 已有 |
| 汇总层 | `output/train.jsonl` | 所有数据集翻译层的汇总 | 已有 |

要点：

- 原始层 = 「如果对同一批选择跑 `export-zips` 会得到的东西」，逐数据集一份。
- 原始层与翻译层**共用同一批已落盘的图片**（`image_store.save` 只调一次，两层记录里的 `images` 路径一致）。
- 原始层**每数据集一份即可**，**不需要**跨数据集的 raw 汇总（使用者未要求）。

### 3.2 `export-zips` 无需改动

`export-zips` 不翻译，其 per-dataset 产出（`output/<dataset>/train_en.jsonl`）**本身就是抽取结果**，已满足「抽取中间文件」的诉求。**本次不给 export 再加 raw 层**，保持现状。

### 3.3 目录布局（D2）

```
output/
  train.jsonl              # 汇总（翻译层）
  train.json
  okvqa/
    raw.jsonl              # 原始层（新增，翻译前英文）
    train.jsonl            # 翻译层
    train.json
  chartqa/
    raw.jsonl
    train.jsonl
    train.json
  ...
  images/<dataset>/<hash>.<ext>
```

`raw.jsonl` 固定文件名，放在各数据集目录下（与 `train.jsonl` 同级）。

## 4. 设计与实现要点

### 4.1 原始层产出（`zip_pipeline.py`）

在重构后的单遍流式管线里，`_iter_dataset_rows` 会对每个「解析通过 + 图片已存」的行 `yield ParsedZipRow`。**在它 yield 之前**（即拿到 `parsed.sample` 和 `image_paths` 之后），若 `emit_raw` 开启，就地写入原始层：

```
raw_record = build_sharegpt_record(item.sample, item.image_paths)
# 写到 output/<dataset>/raw.jsonl（仅当该 id 尚未在 raw 集合中，见 4.2）
```

- 只影响 `run_translate_zips`；`run_export_zips` 不加。
- 建议新增私有 helper（如 `_raw_output_path(config, dataset_name)` 返回 `output/<dataset>/raw.jsonl`），与现有 `_dataset_output_paths` 风格一致。
- 收尾 `_finalize_zip_run`：**只对 raw.jsonl 收尾即可**（是否顺带生成 `raw.json` 不作要求，默认**只出 jsonl**，保持精简）。

### 4.2 ⚠️ resume / 去重 / truncate 交互（本功能最易出错处，必须按此实现）

原始层有**独立于翻译层**的 resume/去重语义，务必分开处理：

1. **独立去重集合**：`run_translate_zips` 开始时（`resume=true`），对每个数据集从已存在的 `raw.jsonl` 载入其 `id` 集合 `raw_done[dataset]`。写 raw 前先判 `sample_id not in raw_done[dataset]`，写完加入。
   - **为什么必须有**：某行第一次运行时 raw 写了、但**翻译失败**（进了 `failed.jsonl`，没进汇总 `output/train.jsonl`）。下次 resume 时，翻译层的 `completed_ids`（来自汇总）不含它 → 它会被**重新处理** → 若不加 raw 去重，raw.jsonl 会**重复写一条**。加了 raw 去重就不会重复。
2. **truncate**：`_prepare_zip_run` 在 `resume=false` 时，除了清空 `output_jsonl`、per-dataset `train.jsonl`、`failed`/`rejected`，**也要清空每个数据集的 `raw.jsonl`**。
3. **已知限制（写进产物注释/文档，可接受，不用额外补偿）**：翻译层 `completed_ids` 的跳过发生在解析之前——若某行在**上一次运行**里已翻译完成（进了汇总），本次 resume 会在解析前直接 `skip`，**不会**再写 raw。因此：
   - 正常场景（raw 从头到尾开着）：上次运行时 raw 已写过该行 → 一致，无缺漏。
   - 边角场景：一个已产生翻译结果的旧任务，**中途才把 `emit_raw` 打开**并 resume → raw 不会回填之前已完成的行。**这是可接受的**，因为 raw（英文）无法从汇总（中文）反推回填。若要完整 raw，请**从头跑**（`resume:false`）或全程开启 raw。

### 4.3 `merge` 命令实现（D3）

- **新增 CLI 子命令** `merge`（风格对齐已有的 `validate`，flag 驱动，不需要 config 文件）：
  ```
  python -m finevision_to_sharegpt merge \
    --inputs output/okvqa/train.jsonl output/chartqa/train.jsonl \
    --output output/merged.jsonl
  ```
- **参数**：
  - `--inputs`：一个或多个 jsonl 路径（`nargs="+"`，必填）。
  - `--output`：输出 jsonl 路径（必填）；对应 json 数组自动写到同名 `.json`（复用 `jsonl_to_json_array`）。
- **行为**：按 `--inputs` 顺序读取所有记录，**按 `id` 去重，先出现者保留**（保持稳定顺序）；无 `id` 字段的记录**全部保留**（无法去重，视为各自唯一）。**不排序、不打乱、不抽样、不改内容。**
- **输出提示**：打印 `read=<总读入> written=<去重后> duplicates=<去掉的重复数> output=<路径>`。
- **实现位置**：在 `json_io.py` 新增纯函数，如 `merge_jsonl_files(inputs: list[Path], output: Path) -> dict[str,int]`，返回统计。CLI 层只做参数解析 + 调用 + 打印。**不要新建 mixer 类模块**，避免重回老路径的模块散落。

### 4.4 config 字段新增

`translate_zips.json`（及 `.example.json`）新增一个可选字段：

```json
"emit_raw": true
```

- `config_loader.py`：`ZipTaskConfig` 增加 `emit_raw: bool = True`；`load_zip_task_config` 读 `bool(data.get("emit_raw", True))`。
- `export_zips.json` **不加**此字段（export 无 raw 层）。

### 4.5 CLI / main 分发

- `build_parser` 增加 `merge` 子命令；`main` 增加 `merge` 分支。
- 保持现有四个命令不变；加完是五个：`translate-json` / `translate-zips` / `export-zips` / `validate` / `merge`。

---

## 5. 不做什么（out of scope）

- 不给 `export-zips` 加 raw 层（其产出已是抽取结果）。
- 不做跨数据集的 raw 汇总文件。
- `merge` **不**引入比例/数量抽样/打乱/加权（严禁复活老 `mix` 逻辑）。
- 不改中英分流 hash、不改 ShareGPT 格式、不改图片落盘规则。
- 不改 `translate-json` 功能。

## 6. 任务拆分（建议顺序）

1. **T1 raw 层**：`config_loader` 加 `emit_raw` → `zip_pipeline` 写 raw + raw 独立去重集合 + truncate 处理（§4.1/4.2）→ 更新 `configs/translate_zips.{json,example.json}`。
2. **T2 merge**：`json_io.merge_jsonl_files` + CLI `merge` 子命令（§4.3）。
3. **T3 测试**：新增/更新 `test_zip_pipeline.py`（raw 层 + resume 去重）、`test_json_io.py` 或 `test_cli.py`（merge 去重/无 id/统计）。
4. **T4 文档**：`README.md`、`docs/运行说明.md` 补充中间文件说明与 `merge` 用法。

## 8. 风险与注意

- **raw 去重是硬要求**：§4.2 第 1 点若漏实现，翻译失败重试会让 raw.jsonl 出现重复记录——这是最可能被忽略的 bug，测试必须覆盖。
- **别把 raw 写进热路径的错误位置**：raw 要在「图片已存、解析通过」之后、翻译决策之前写，且受 `emit_raw` 与 raw 去重集合双重控制。
- **merge 保持极简**：一旦发现自己在写「按比例/按数量取样」，就是走错方向了——那是被删掉的老 `mix`，不要复活。
- **等价性**：raw 层是**新增旁路**，不得改变翻译层/汇总层的任何既有产物字节。加完后旧的 `test_zip_pipeline` 断言应仍通过（除非显式更新）。
