# 开发文档：翻译 + 数据抽样模块重构

> 文档角色：这是给**执行编码的 AI**看的需求与验收文档。项目经理（本文作者）负责验收，不直接改代码。
> 日期：2026-07-27　范围：`finevision-to-sharegpt` 的「翻译 + 数据抽样」子系统。

---

## 1. 背景与目标

当前项目有**三个对外文档化的功能**：`translate-json` / `translate-zips` / `export-zips`（见 `README.md`）。
但代码里同时存在**一套未文档化的老路径**（`translate` / `sample` / `mix` 三个 CLI 命令 + `sampler.py` + `mixer.py` + `sample_config`），与主路径的抽样/混流逻辑**功能重叠、互相冗余**。同时任务配置文件字段冗杂、有死字段、嵌套多余，`zip_pipeline.py` 里两条流水线大量重复。

**本次重构目标（按优先级）：**

1. **删除老路径**，让「从 zip 抽样 + 翻译」只有一条清晰实现。
2. **精简任务配置**（去死字段、拍平多余嵌套、输出路径可缺省），降低使用者要手写的字段量。
3. **消除 `zip_pipeline.py` 两条流水线的重复代码**，提升可维护性。

**非目标（本次不做）：**

- 不改 backend 并发/重试机制（`backend_pool.py` / `concurrency.py` / `qwen_client.py`）。
- 不改中英分流算法本身（`should_translate_to_chinese` 的 hash 逻辑保持不变）。
- 不改 ShareGPT 输出格式、`<image>` token 规则、图片落盘规则。
- 不引入新的数据源类型或输出格式。
- 不强制引入 `output_dir` 单目录推导模式（见 §5.2 决策）。

## 3. 现状问题清单（带证据）

### 3.1 老路径冗余（对应 D1）

- CLI 里有 6 个子命令，其中 **3 个未在 README 出现**：
  - `translate`（`cli.py:42`）——纯命令行 flag 驱动的一次性转换，逻辑与 `translate-zips` 重叠。
  - `sample`（`cli.py:93`）——基于 `sampler.py` 的 recipes 抽样。
  - `mix`（`cli.py:119`）——基于 `mixer.py` 的 jsonl 混合。
- `sampler.py` 用的是**另一套抽样模型**（`SampleRecipe` / `SampleDatasetPlan`，`{zip, english, chinese}` / `{count, language_mix}`），与主路径的 `ZipTaskConfig` + `chinese_ratio` 完全平行。
- 对应配置文件 `configs/sample_config.example.json` 也是独立的一套。
- 老命令拖入大量**仅供其使用**的 helper（需执行方逐一确认无其他引用后删除）：
  `run_translate`(`cli.py:257`)、`run_sample`(`cli.py:501`)、`_make_limiter`、`_flush_translation_batch`、`_record_batch_result`、`_progress_bar`、`_update_progress`、`_ensure_output_dirs`、`_load_completed_ids`、`_append_jsonl`、`_reject_record`、`_record_to_source_sample`、`_as_list`、`_parse_mix_input` 等。

### 3.2 配置冗杂（对应 D2）

以 `configs/translate_zips.json` 为例：

- **输出路径全手写**：`output_jsonl` / `output_json` / `failed_path` / `rejected_path` / `report_path` / `images_root` 六个字段。其中 `failed_path`/`rejected_path`/`report_path` 在 `config_loader.py:131-133` **本就有缺省推导**，却仍写死在配置里。
- **死字段**：`language.mode`（`config_loader.py:126` 加载，但全代码库**从无读取**，已确认）。
- **多余嵌套**：`limits.limit_per_dataset` 为单字段套一层 `limits`（`config_loader.py:117,136`）。
- `translate_zips.json` 与 `export_zips.json` 字段大面积重复。

### 3.3 代码重复（对应重构目标 3）

- `zip_pipeline.py` 的 `run_export_zips`（`:37`）与 `run_translate_zips`（`:107`）**约 80% 结构重复**：都做「选数据集 → resume 处理 → 遍历 parquet 行 → parse → 存图 → 写记录 → 更新统计 → 收尾转 json + 写 report」。区别只在中间「是否走翻译分流」。

## 5. 目标设计

### 5.1 数据集注册表（D3，保持现状）

`configs/datasets.json` 结构与 `dataset_registry.py` **不变**。任务配置继续用 `dataset_registry` 指向它、用 `datasets` 数组按名字选取。

### 5.2 新的任务配置结构（D2：中度精简）

**原则**：`output_jsonl` 为唯一锚点，其余输出路径全部可缺省并自动推导；删死字段；拍平单字段嵌套；保留所有覆盖能力（谁想手写照样能写）。

#### `translate_zips.json` 目标结构

```json
{
  "dataset_registry": "configs/datasets.json",
  "datasets": ["*"],
  "output_jsonl": "output/train.jsonl",
  "chinese_ratio": 1.0,
  "seed": 42,
  "limit_per_dataset": null,
  "backend_config": "configs/backend_config.json",
  "sample_prompt_file": "prompts/translate_sample_zh.txt",
  "utterance_prompt_file": "prompts/translate_utterance_zh.txt",
  "resume": true
}
```

变化点：

1. **删 `output_json` / `images_root` / `failed_path` / `rejected_path` / `report_path` 的强制书写**，改为缺省推导（下表），字段仍**允许**出现以覆盖。
2. **删 `language` 包裹层与死字段 `mode`**：`chinese_ratio`、`seed` 提到顶层。
3. **删 `limits` 包裹层**：`limit_per_dataset` 提到顶层。

缺省推导规则（在 `config_loader.py` 实现，以 `output_jsonl` 的目录 `OUT` 和主干名 `STEM` 为基准）：

| 字段 | 缺省值 |
|------|--------|
| `output_json` | `OUT/STEM.json` |
| `images_root` | `OUT/images` |
| `failed_path` | `OUT/failed.jsonl` |
| `rejected_path` | `OUT/rejected.jsonl` |
| `report_path` | `OUT/report.json` |

> 注：现有 `config_loader.py` 已经用 `output_jsonl.with_name(...)` 推导 failed/rejected/report，本次把 `output_json` 和 `images_root` 也纳入同规则，并让默认配置文件不再写死它们。

#### `export_zips.json` 目标结构

```json
{
  "dataset_registry": "configs/datasets.json",
  "datasets": ["*"],
  "output_jsonl": "output/train_en.jsonl",
  "limit_per_dataset": null,
  "resume": true
}
```

（无翻译，故无 `chinese_ratio`/`seed`/`backend`/`prompt`；其余同上推导。）

#### 每数据集覆盖（保持能力，字段随顶层同步改名）

```json
"datasets": [
  "okvqa",
  { "name": "captcha", "chinese_ratio": 1.0, "limit": 5000 }
]
```

`DatasetRequest`（`config_loader.py:41`）保持 `name` / `chinese_ratio` / `limit` 三字段不变。

#### `config_loader.py` 改造要点

- `LanguageConfig` dataclass：**删除**，`chinese_ratio`/`seed` 直接进 `ZipTaskConfig`；或保留 dataclass 但去掉 `mode` 字段——**二选一，推荐直接删 `LanguageConfig`**，让 `ZipTaskConfig` 扁平持有 `chinese_ratio: float = 1.0`、`seed: int = 42`。
- `load_zip_task_config`：读取顶层 `chinese_ratio`/`seed`/`limit_per_dataset`；补 `output_json`/`images_root` 的缺省推导。
- **向后兼容**：这些是内部配置文件，**允许破坏旧格式**，但为降低误伤，建议对旧字段做**兼容读取**：若检测到 `language`/`limits` 嵌套仍能解析（读到就用，同时不再写出）。是否保留兼容读取由执行方权衡，**但默认配置文件必须改成新结构**。
- 同步更新 `configs/*.example.json` 与实际 `configs/*.json` 到新结构。
- 同步更新 `README.md` 与 `docs/运行说明.md` 中的配置示例。

### 5.3 `zip_pipeline.py` 去重（重构目标 3）

把 `run_export_zips` 与 `run_translate_zips` 的公共骨架抽成**一个内部遍历函数**，通过回调/策略区分「英文直出」与「中文送翻译」两种每行处理。建议方向（执行方可微调命名）：

- 抽出 `_iter_dataset_rows(config, datasets, ...)`：负责 resume 判定、`parse_row`、存图、统计更新、进度条，产出「已解析 + 图片路径 + sample_id + dataset」的中间对象。
- `export`：对每个中间对象直接 `build_sharegpt_record` 写盘。
- `translate`：对每个中间对象按 `should_translate_to_chinese` 决定 `yield TranslationTask`（走 backend_pool）或英文直出。
- 收尾逻辑（`jsonl_to_json_array` 汇总 + 每数据集转 json + 写 report + `prune_failed`）抽成共用函数。

**硬约束**：重构后**行为完全等价**——sample_id 生成规则、resume 跳过、每数据集 limit 判定、统计字段（processed/written/english/chinese/rejected/failed/skipped）、report 结构、per-dataset jsonl/backfill 行为**全部不变**。这是纯内部重构，对外产物字节级一致（除非因去重发现的既有 bug，需单独标注征询）。

## 8. 风险与注意事项

- **删 helper 前必须确认引用**：`cli.py` 中若干 `_xxx` helper 名字与 `json_io.py` 公共函数重名，勿误删公共设施（§4 警告）。
- **中英分流 hash 不能动**：`should_translate_to_chinese` 改一个字符都会导致同一 `id` 落到不同语言，破坏 resume 一致性。
- **等价性优先于优雅**：§5.3 去重若与「保持行为完全一致」冲突，以一致为准；发现疑似既有 bug 请**单独标注上报**，不要顺手改。
- **配置为内部文件**：可破坏旧格式，但默认配置与文档必须同步，避免使用者拿旧配置跑报错却无提示——`config_loader` 对缺失必填字段应给**清晰报错信息**。
```
