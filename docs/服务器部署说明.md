# 服务器部署说明（受限环境）

适用场景：一台**什么都没装**的服务器，**根目录不可写**，只有 `/mnt` 可写，已装好 conda。
从新建 conda 环境开始，一路到跑出训练数据。

全文假设可写目录是 `/mnt`。如果你的可写路径不同，把下面所有 `/mnt/fv` 换掉即可。

---

## 第 0 步：先搞清楚三件事

在动手之前确认这三点，能省掉后面 90% 的坑：

```bash
# 1. 哪些目录能写？
touch /mnt/.writetest && echo "/mnt 可写" && rm /mnt/.writetest
touch ~/.writetest 2>/dev/null && echo "HOME 可写" && rm ~/.writetest || echo "HOME 不可写 —— 必须做第 2 步的重定向"
touch /tmp/.writetest 2>/dev/null && echo "/tmp 可写" && rm /tmp/.writetest || echo "/tmp 不可写 —— 必须设 TMPDIR"

# 2. /mnt 还有多少空间？（下面第 7 步会算你到底需要多少）
df -h /mnt

# 3. 能不能连外网装包？
curl -sS -m 10 https://pypi.org/simple/ -o /dev/null && echo "外网通，走在线安装" || echo "外网不通，走离线安装"
```

**HOME 不可写是最容易翻车的一点**：conda 和 pip 默认都往 `$HOME` 里写缓存和配置，不重定向的话第一条命令就报 `Permission denied`。

---

## 第 1 步：建目录结构

```bash
mkdir -p /mnt/fv/{envs,pkgs,pipcache,tmp,code,data/zips,output}
```

| 目录 | 用途 |
| --- | --- |
| `/mnt/fv/envs` | conda 环境 |
| `/mnt/fv/pkgs` | conda 包缓存 |
| `/mnt/fv/pipcache` | pip 缓存 |
| `/mnt/fv/tmp` | **临时目录，解压 zip 用，需要很大**，见第 7 步 |
| `/mnt/fv/code` | 代码 |
| `/mnt/fv/data/zips` | 你的数据集 zip |
| `/mnt/fv/output` | 产出的训练数据和图片 |

---

## 第 2 步：把所有默认写入路径重定向到 /mnt

建一个环境文件，**以后每次登录、每个脚本都先 source 它**：

```bash
cat > /mnt/fv/env.sh <<'EOF'
# conda：环境和包缓存都不放 HOME
export CONDA_ENVS_DIRS=/mnt/fv/envs
export CONDA_PKGS_DIRS=/mnt/fv/pkgs

# pip：缓存不放 HOME
export PIP_CACHE_DIR=/mnt/fv/pipcache

# 临时目录：解压 zip 会往这里写几十 GB，绝不能用默认的 /tmp
export TMPDIR=/mnt/fv/tmp

# MySQL 密码（用到 db 模式时才需要，别写进 git）
export FV_MYSQL_PASSWORD='改成你的密码'
EOF

source /mnt/fv/env.sh
```

`TMPDIR` 这条是本项目**特有的硬要求**，不是通用建议 —— 原因见第 7 步。

如果做完这些还有东西往 HOME 里写导致报错，最后的兜底是连 `HOME` 一起改：

```bash
export HOME=/mnt/fv/home && mkdir -p "$HOME"
```

---

## 第 3 步：建 conda 环境

项目要求 **Python ≥ 3.11**。

```bash
source /mnt/fv/env.sh
conda create -p /mnt/fv/envs/fv python=3.11 -y
conda activate /mnt/fv/envs/fv
python -V   # 应该显示 3.11.x
```

注意用 `-p`（指定完整路径）而不是 `-n`（放进 conda 自带的 envs 目录）。如果 conda 装在不可写的位置，`-n` 会失败。

---

## 第 4 步：装包

### 运行时只需要 4 个包

```bash
pip install "httpx>=0.27,<1" "pyarrow>=15,<22" "tqdm>=4,<5" "PyMySQL>=1.1,<2"
```

说明：

- `requirements.txt` 里还有 `Pillow` 和 `pytest`。**这两个跑起来用不到**：`pytest` 只在跑测试时要；`Pillow` 源码里根本没 import（处理 PIL 图片走的是鸭子类型判断），装了纯属浪费带宽。要跑测试再补 `pip install pytest`。
- `PyMySQL` 只有用 MySQL 模式才需要。纯文件模式可以不装。
- 最大的包是 `pyarrow`（约 40 MB wheel，装完约 200 MB）。

### 外网不通就走离线

在一台**能上网、同架构（Linux x86_64）、同 Python 版本**的机器上先下好：

```bash
pip download --only-binary=:all: --platform manylinux2014_x86_64 \
  --python-version 311 --implementation cp -d ./wheels \
  "httpx>=0.27,<1" "pyarrow>=15,<22" "tqdm>=4,<5" "PyMySQL>=1.1,<2"
tar czf wheels.tar.gz wheels
```

拷到服务器后：

```bash
tar xzf wheels.tar.gz -C /mnt/fv/
pip install --no-index --find-links=/mnt/fv/wheels \
  httpx pyarrow tqdm PyMySQL
```

## 第 5 步：放代码

```bash
cd /mnt/fv/code
git clone https://github.com/liugenzzz/finevision-to-sharegpt.git
cd finevision-to-sharegpt
```

外网不通就在本地打包传上去：

```bash
# 本地
git archive --format=tar.gz -o fv.tar.gz HEAD
# 服务器
mkdir -p /mnt/fv/code/finevision-to-sharegpt
tar xzf fv.tar.gz -C /mnt/fv/code/finevision-to-sharegpt
```

**不需要 `pip install .`**。项目自带的脚本会自己设 `PYTHONPATH=src`，直接跑就行。

验证一下能用：

```bash
source /mnt/fv/env.sh
conda activate /mnt/fv/envs/fv
cd /mnt/fv/code/finevision-to-sharegpt
PYTHONPATH=src python -m finevision_to_sharegpt --help
```

看到命令列表就算装好了。

## 第 6 步：放数据和改配置

### 数据

把 zip 放进 `/mnt/fv/data/zips/`，然后注册：

```bash
cat > configs/datasets.json <<'EOF'
{
  "data_root": "/mnt/fv/data/zips",
  "datasets": {
    "okvqa":   { "zip": "okvqa.zip" },
    "chartqa": { "zip": "chartqa.zip" }
  }
}
EOF
```

### 模型后端

```bash
cat > configs/backend_config.json <<'EOF'
{
  "request_timeout": 120,
  "max_retries": 2,
  "disable_backend_after_failures": 20,
  "backends": [
    { "name": "gpu0", "api_base": "http://10.0.0.1:18180/v1/chat/completions",
      "model": "Qwen3-VL", "api_key": "sk-local", "concurrency": 16, "weight": 1 },
    { "name": "gpu1", "api_base": "http://10.0.0.2:18180/v1/chat/completions",
      "model": "Qwen3-VL", "api_key": "sk-local", "concurrency": 24, "weight": 1 }
  ]
}
EOF
```

多卡多模型就多写几个 backend，`concurrency` 是每个 backend 的固定并发。

### 任务配置

```bash
cat > configs/translate_zips.json <<'EOF'
{
  "dataset_registry": "configs/datasets.json",
  "datasets": ["*"],
  "output_jsonl": "/mnt/fv/output/train.jsonl",
  "chinese_ratio": 1.0,
  "seed": 42,
  "limit_per_dataset": 5000,
  "backend_config": "configs/backend_config.json",
  "emit_raw": true,
  "resume": true
}
EOF
```

**输出路径写成 `/mnt` 下的绝对路径**，别用相对路径掉进不可写的地方。

## 第 7 步：算清楚磁盘和内存（重要）

这一步不是走过场，本项目解压 zip 的方式决定了两个硬性下限：

`extract_parquets_from_zip` 处理一个数据集时，会把**这个 zip 里所有 parquet 一次性全解压**到 `TMPDIR`，而且每个成员是**整个读进内存**再写盘的（`target.write(source.read())`）。所以：

| 资源 | 下限 | 怎么估 |
| --- | --- | --- |
| `TMPDIR` 可用空间 | ≥ **单个 zip 解压后的总大小** | 用下面的脚本 |
| 可用内存 | ≥ **该 zip 里最大的那个 parquet 成员** | 用下面的脚本 |
| 输出目录 | 图片总量 + JSONL | 图片按内容 hash 去重落盘，重复图只存一份 |

仓库里带了个脚本直接帮你算，还会拿 `TMPDIR` 的实际剩余空间对比给结论：

```bash
source /mnt/fv/env.sh
python scripts/estimate_space.py /mnt/fv/data/zips
```

输出长这样：

```text
okvqa.zip
  members     : 12
  uncompressed:    48.30 GB
  largest one :     4.10 GB

TMPDIR needs at least :    48.30 GB
free memory at least  :     4.10 GB

TMPDIR=/mnt/fv/tmp has 512.00 GB free -> OK
```

空间不够时会打印 `TOO SMALL` 并以非 0 退出码结束，方便串进部署脚本里做前置检查。

`TMPDIR` 空间不够的典型症状是跑到一半 `No space left on device`。内存不够则是 OOM 被杀。

多个数据集是**逐个处理**的，临时目录用完即清，所以按**最大的那一个** zip 算就够，不用把所有 zip 加起来。

## 第 8 步：跑起来

### 先小规模试一次

把 `limit_per_dataset` 临时改成 `10`，确认整条链路通：

```bash
source /mnt/fv/env.sh
conda activate /mnt/fv/envs/fv
cd /mnt/fv/code/finevision-to-sharegpt

bash scripts/in_translate_zips.sh
```

检查产出：

```bash
wc -l /mnt/fv/output/train.jsonl
cat /mnt/fv/output/report.json
head -c 500 /mnt/fv/output/train.jsonl
```

`report.json` 里 `failed` 不为 0 就去看 `/mnt/fv/output/failed.jsonl`，通常是模型接口不通或超时。

### 不翻译，只导出英文

```bash
bash scripts/in_export_zips.sh
```

这条不需要 `backend_config.json`，可以用来**在配模型之前先验证数据侧是否正常**。建议第一次部署就先跑这个。

### 正式跑（长任务后台化）

```bash
nohup bash scripts/in_translate_zips.sh > /mnt/fv/output/run.log 2>&1 &
tail -f /mnt/fv/output/run.log
```

中断了直接重跑同一条命令即可，`resume: true` 会按 `id` 跳过已完成的样本。

### 校验输出

```bash
PYTHONPATH=src python -m finevision_to_sharegpt validate \
  --input  /mnt/fv/output/train.jsonl \
  --output /mnt/fv/output/train.clean.jsonl \
  --rejects /mnt/fv/output/train.rejected.jsonl
```

## 第 9 步（可选）：接 MySQL 做增量抽取

**不配就完全用不到**，上面的流程本身是完整的。需要"用多少抽多少、跨任务不重复"时再来这一步。

### 你得先有一个 MySQL 8.0

这个项目**不负责装 MySQL**。三种来源：

1. 已有内网 MySQL —— 建个库和账号就行（推荐）：

   ```sql
   CREATE DATABASE finevision CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
   CREATE USER 'fv'@'%' IDENTIFIED BY '你的密码';
   GRANT ALL PRIVILEGES ON finevision.* TO 'fv'@'%';
   FLUSH PRIVILEGES;
   ```

2. 服务器上有 docker —— 用仓库里的 `docker-compose.yml`：`docker compose up -d mysql`
3. 都没有 —— conda 也能装，但不推荐在生产这么干：`conda install -c conda-forge mysql-server`

### 配置

在任务配置里加一段 `mysql`：

```json
{
  "mysql": {
    "host": "10.0.0.5",
    "port": 3306,
    "user": "fv",
    "password": "${FV_MYSQL_PASSWORD}",
    "database": "finevision",
    "batch_size": 200,
    "claim_ttl_seconds": 3600,
    "on_connect_error": "fallback"
  }
}
```

密码走 `${FV_MYSQL_PASSWORD}` 环境变量（已经在 `env.sh` 里设好了），不要写死进文件。

### 建表并使用

```bash
bash scripts/in_db_init.sh configs/translate_zips.json    # 建表，幂等
bash scripts/in_translate_zips.sh                          # 抽 5000 条
bash scripts/in_translate_zips.sh                          # 再抽 5000 条全新的
bash scripts/in_db_status.sh configs/translate_zips.json   # 看各状态计数
```

`limit_per_dataset` 是**本次新增 N 条**的意思，所以重复运行就是不断往下抽新数据，两次的输出目录不同也不会重复。

## 常见问题

| 症状 | 原因 | 解决 |
| --- | --- | --- |
| `Permission denied` 在装包时 | conda/pip 往 HOME 写 | 第 2 步的 `CONDA_PKGS_DIRS` / `PIP_CACHE_DIR` |
| `No space left on device` 跑到一半 | `TMPDIR` 太小 | 第 2 步设 `TMPDIR=/mnt/fv/tmp`，并按第 7 步核对空间 |
| 进程被 OOM kill | 单个 parquet 成员太大 | 见第 7 步，内存要 ≥ 最大单成员 |
| `No module named finevision_to_sharegpt` | 没设 PYTHONPATH | 用 `scripts/in_*.sh`，它会自己设；或手动 `export PYTHONPATH=src` |
| `environment variable FV_MYSQL_PASSWORD ... is not set` | 没 source `env.sh` | `source /mnt/fv/env.sh` |
| 翻译全部 failed | 模型接口不通 | `curl` 试一下 `api_base`；看 `failed.jsonl` 里的 error |
| MySQL 连不上但任务照跑 | `on_connect_error: "fallback"` 的预期行为 | 想让它直接报错就改成 `"fail"` |
| 建表报 collation 不存在 | 服务端不是 MySQL 8.0 | 在 `mysql` 段加 `"collation": "utf8mb4_general_ci"` |
